# Страница «О себе»

Локальный учебный редактор с тремя последовательными задачами: HTML и CSS; семантика, классы и фото по QR; Flexbox и четыре карточки интересов. Перед каждой задачей открывается теория. Внизу — прогресс, ближайший шаг, список действий и поздравление на 100%.

[Подробный сценарий](LESSON.md).

## Запуск

```sh
cd web-lab
python3 -B server.py
```

Python 3.9+, без установки пакетов. На компьютере: http://127.0.0.1:4173/. Сервер печатает сетевой адрес для телефонов и остальных компьютеров класса.

Для локального запуска QR оба устройства должны быть в одной сети с доступом к порту 4173. Если адрес выбран неверно, укажите его:

```sh
python3 -B server.py --public-url http://192.168.1.10:4173
```

Обычный статический сервер поддерживает редактор и встроенную библиотеку, но не передачу по QR. Для полной второй задачи нужен `server.py`.

Для Dokploy в корне репозитория есть Dockerfile: он запускает редактор и QR API вместе на порту 80. Выберите сборку Dockerfile и сделайте Deploy — nginx и systemd настраивать не нужно. [Настройки Dokploy для school.tube-city.ru](deploy/README.md). Общая Wi-Fi-сеть для опубликованного сайта не требуется.

## Редактор

Три панели: блоки, предпросмотр и настройки. Доступны режимы «Блоки», HTML, CSS. Предпросмотр всегда использует ширину 720 px.

В общем пуле восемь блоков: h1, h2, p, div, article, section, figure, img. Подменю «Ещё блоки», список, ссылка и кнопка удалены. Article и figure добавляются пустыми: ученики собирают содержимое сами.

Скобки, линии и отступы показывают вложенность. При перетаскивании пустой контейнер раскрывается. Вместо перетаскивания можно выбрать контейнер и нажать блок в библиотеке; существующие элементы можно переносить через поле «Родитель».

Класс назначается в «CSS-классы» после завершения ввода. Кнопки с именами назначенных классов открывают их оформление. «Стиль класса» определяет, какое правило изменяется; настройки создают настоящий CSS. Для ширины контейнера и картинки есть отдельные ползунки.

## Проверка задач

`lesson.js` содержит теорию и детальные проверки. Процент — доля реально выполненных действий текущей задачи; следующие задачи открываются после завершения предыдущих. Проверка запускается после изменений, выбора блока, редактирования кода и сохранения.

На 100% появляется поздравление; переход требует нажатия кнопки и открывает следующую теорию. Автоперехода во время ввода нет. При отмене изменений или удалении нужного блока процент уменьшается. Недостающий предыдущий шаг нельзя скрыть выполнением последней задачи.

Проверяются фон именно `.page`, собственный текст, соседство `hero_item` и `hero_img`, происхождение фото из QR, его описание и настройка, Flexbox у hero, четыре карточки с двумя абзацами и картинками, общие CSS-правила и одинаковое оформление.

## Картинки

Шесть фото включены в `assets/`, источники — `assets/credits.json`. QR создаётся локальной MIT-библиотекой Project Nayuki из `vendor/`. Загрузка с компьютера отсутствует.

На телефоне доступны JPG, PNG, WebP и GIF. Фото преобразуется в JPG до 960 px и 220 000 символов data URL. GIF становится статичным; HEIC нужно предварительно сохранить в JPG. QR действует 10 минут и принимает одну картинку. Закрытие QR или успешный приём удаляет временный сеанс из памяти сервера. Сама картинка сохраняется в HTML проекта.

Картинка вставляется в выбранный контейнер. Если там уже есть прямая дочерняя img, она заменяется. Поэтому можно независимо добавлять фото в hero и в каждую карточку. Сам img можно вставить прямо в hero и дать ему класс hero_img; figure необязателен. Проверка урока принимает оба варианта.

### Изоляция QR-сеансов

Каждый QR получает случайные независимые идентификатор сеанса, ключ чтения для компьютера и ключ отправки для телефона. Ссылки не используют имя проекта, номер компьютера или общий адрес загрузки без ключа. Фото передаётся только сеансу из отсканированной ссылки; ключ соседнего сеанса не позволяет читать или закрывать чужой. После получения фото, закрытия окна или истечения срока прежняя ссылка не переключается на новый сеанс.

Проверено HTTP-тестом: 30 одновременных сеансов с 30 различными изображениями, каждое вернулось своему получателю. DOM-тесты дополнительно проверяют два независимых редактора, переключение проекта во время запроса, закрытие окна и запоздалое создание старого QR.

Привязка действует к конкретной QR-ссылке, без входа в учётную запись ученика. Если человек сканирует чужой QR или получает чужую ссылку, он отправляет фото владельцу этого QR.

## Сохранение

Автосохранение использует localStorage текущего браузера и адреса. «Сохранить» создаёт контрольную версию (до шести на проект). «Проекты» позволяет переключаться между работами. Новый сценарий создаёт новую заготовку при первом открытии; прежние проекты сохраняются.

«Результат → Код проекта» выдаёт переносимый WL1-код с HTML, CSS, картинками и состоянием задач. Импорт: «Проекты → Открыть по коду». Ограничение — 700 000 байт распакованного проекта. Большое число фото и версий может заполнить localStorage; тогда сохраните код отдельно.

## Проверки

Без дополнительных пакетов:

```sh
node --check app.js
node --check lesson.js
node --check photo.js
node --check upload.js
python3 -B -m unittest discover -s tests -v
```

Интеграционные DOM-тесты задач используют jsdom только для разработки; приложению он не нужен. Его можно установить во временную папку:

```sh
npm install --prefix /tmp/workshop-lesson-qa --no-audit --no-fund --package-lock=false jsdom
NODE_PATH=/tmp/workshop-lesson-qa/node_modules node --test tests/test_lesson.cjs
```

Они проверяют теорию и переходы, частичный прогресс, поздравление, вложенность, QR-происхождение, вставку в выбранную карточку, единые стили и восстановление состояния.

Файлы: `app.js` — редактор; `lesson.js` — задачи и теория; `index.html`, `app.css` — интерфейс; `server.py` — локальный сервер; `photo.js`, `upload.*` — подготовка и отправка фото с телефона.
