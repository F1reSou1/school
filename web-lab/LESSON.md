# Страница «О себе»: три практические задачи

Каждая задача начинается с модального окна: короткая теория, пример структуры и список действий. «Начать задачу» открывает редактор. Теорию можно перечитать кнопкой «Теория» внизу.

Внизу постоянно видны задание, процент выполнения, выполненные действия и ближайший незавершённый шаг. «К шагу» выбирает нужный блок. Весь список действий раскрывается отдельно. На 100% появляется поздравление и кнопка перехода. Следующая задача открывается через свою теорию; редактор сам не переключает ученика.

## 1. HTML, CSS, блоки и классы

**Теория:** HTML задаёт содержимое и вложенность; CSS — оформление. Теги ограничивают элементы, контейнер включает детей. Класс связывает `class="page"` с правилом `.page { … }`. Один класс можно назначить нескольким элементам.

**Задача:**

1. Выбрать `main.page` и класс `page`.
2. Изменить фон у `.page`.
3. Вписать имя в `h1`.
4. Изменить абзац знакомства в `header.hero`.

Каждое действие даёт 25%. Фон другого блока не засчитывается как фон страницы. Можно использовать вымышленное имя.

## 2. Семантика, БЭМ и вступление

**Теория:** роль `main`, `header`, `section`, `article`, `div`, `figure`, `img`, `h1`, `h2`, `p`, `footer`. Скринридерам семантика помогает находить разделы и заголовки; поисковым роботам — понимать структуру. Значимое изображение получает описание `alt`.

БЭМ: блок, элемент, модификатор; распространённая запись — `hero`, `hero__item`, `hero__item--wide`. В упражнении сохранены заданные имена `hero_item` и `hero_img` с одним подчёркиванием. В теории явно сказано, что это учебные имена, а не стандартная запись элемента БЭМ.

**Задача:**

1. В `header.hero` создать `div.hero_item`.
2. Переместить существующие `h1` и `p` внутрь этого контейнера.
3. Рядом, также внутри `hero`, добавить `img.hero_img`.
4. Заменить изображение своим фото с телефона по QR.
5. Написать собственный `alt`.
6. Изменить ширину, скругление или пропорции картинки.

Вступление должно иметь такую вложенность:

```text
header.hero {
  div.hero_item { h1, p }
  img.hero_img
}
```

Для `img` обёртка не нужна. Варианты `figure.hero_img { img }` и `div.hero_img { img }` также засчитываются. `figure` обозначает самостоятельную иллюстрацию и может содержать подпись `figcaption`.

Перенос доступен и перетаскиванием, и через поле «Родитель». Фото добавляется в выбранный контейнер, повторный выбор заменяет его прямую дочернюю картинку. Готовые фото доступны, но шаг «через QR» выполняется только после фактического получения фото от телефона. Описание и настройки проверяются отдельно.

## 3. Flexbox и четыре карточки

**Теория:** Flexbox включается у родителя и располагает прямых детей. `row` — строка, `column` — колонка, `gap` — расстояние, `justify-content` и `align-items` управляют разными осями. При смене направления оси меняются местами. Общие классы обеспечивают единое оформление.

**Задача:**

1. У `header.hero` включить Flexbox в строку.
2. Уменьшить фото до 240 px или меньше.
3. В разделе «Мои интересы» создать `article.interesting`.
4. Вложить в него четыре `div` с общим классом, например `interesting_card`.
5. В каждой карточке создать два `p`: `interesting_title` и `interesting_description`, заполнить их своим текстом и вставить картинку с `alt`.
6. Настроить общий класс карточек и оба текстовых класса.

Каждая карточка проверяется отдельно: её наличие, название, описание и фото. Нужны ровно четыре карточки, реальные CSS-правила общих классов и одинаковые настройки у соответствующих элементов. Нельзя получить 100% одной карточкой или только перечислением имён классов без оформления.

Удобный путь: собрать первую карточку, настроить классы, дублировать её три раза кнопкой ⧉ и заменить содержание в копиях.

После 100% у всех трёх задач ученик сохраняет страницу. Если предыдущая задача стала неполной после редактирования, редактор предложит вернуться к ней.

## Запуск и сохранение

```sh
cd web-lab
python3 -B server.py
```

Компьютер и телефон для QR должны находиться в одной сети. Если сеть изолирует устройства, это нужно решить до урока: библиотека картинок не заменяет проверку передачи по QR.

Прогресс, просмотренные теоретические вводные и информация об отправленных картинках сохраняются вместе с проектом. При обновлении сценария создаётся новая заготовка, прежние работы остаются в «Проекты».

Источники теории: [семантика HTML · MDN](https://developer.mozilla.org/en-US/docs/Glossary/Semantics), [БЭМ](https://getbem.com/naming/), [Flexbox · MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Basic_concepts).
